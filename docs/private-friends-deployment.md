# Закрытый экземпляр для друзей

Этот профиль выбран владельцем вместо допуска к публичным коммерческим продажам.
Он не создаёт фиктивных production approval, юридических реквизитов или результатов
проверок. `NODE_ENV=production`, HTTPS, Secure/HttpOnly cookies, CSRF, Telegram
initData, роли, изоляция сети/БД, миграции и финансовые инварианты сохраняются.

В `ops/docker/production.env` явно задать `WATCH_PRIVATE_ACCESS=1`, реальные
`ADMIN_TELEGRAM_IDS` и, по необходимости, `PRIVATE_TELEGRAM_IDS` (через запятую).
Вход разрешён только объединению этих списков. Удалённый из списка пользователь
теряет доступ и с уже выданной сессией после пересоздания API. Администраторы
сохраняют отдельную роль: включение друга в private list не даёт admin-доступа.
Доступ к SSH и production.env следует сохранять только у оператора.

По явному решению владельца `WATCH_PUBLIC_SHOP=1` открывает вход в магазин всем
пользователям с проверенным Telegram initData, независимо от PRIVATE_TELEGRAM_IDS.
Администраторами остаются только ADMIN_TELEGRAM_IDS; индивидуальные блокировки,
CSRF и проверки партнёрских прав сохраняются. Пустое или отсутствующее значение
возвращает ограничение списком. Настройка меняет доступ покупателей, но не является
коммерческим approval и не обновляет опубликованные уведомления автоматически.
После изменения нужно пересоздать API; одного restart недостаточно.

Для пустого каталога допускается ещё не инициализированный native-склад: такой
товар остаётся UNKNOWN и не продаётся. Инициализированные остатки нельзя вернуть
в legacy mode. Не импортировать синтетические TEST-INV строки как реальные.

`compose.mjs` автоматически добавляет `compose.private.yml` после native overlay.
Профиль убирает коммерческий approval mount. Bootstrap всё ещё проверяет точные
hashes/версии/effectiveAt трёх операционных уведомлений и согласованную валюту,
но не выдаёт их за одобренную публичную оферту. Пустые/фиктивные реквизиты в них
не нужны: достаточно описать фактическую закрытую работу и связь с администратором.

Использовать чистый checkout с release SHA и соответствующим RELEASE_TAG:

```sh
node ops/scripts/deploy-private.mjs prepare
# Штатный provision-admin после bootstrap, с реальным Telegram ID и именем.
node ops/scripts/deploy-private.mjs start
```

Prepare запускает только PostgreSQL, миграции и bootstrap, оставляя writers/proxy
остановленными. Start использует штатный stage с readiness/financial/migration
проверками, затем открывает proxy и проверяет HTTPS, health/ready, web, заголовки
и отказ в доступе к session/legal routes без сессии. При ошибке proxy закрывается.
После этого настраиваются webhook/menu и проверяется реальный Telegram-вход.

Этот профиль не утверждает наличие ежедневного зашифрованного backup/host-loss
restore. Выбранное владельцем ограничение расходов и фактический способ копирования
документируются отдельно. Бесплатная копия провайдера не считается проверенным
восстановлением БД и медиа. Переход к публичному коммерческому запуску — отдельная
задача: выключение private flag вернёт обязательные production approvals;
стандартный deploy.mjs не подменяется этим профилем.
