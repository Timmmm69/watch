# Владельцу: реферальные продажи

Действующая модель определена в [FULL_BUILD_SPEC.md §31](../FULL_BUILD_SPEC.md#31-final-business-decision--2026-10-22).

Покупатель самостоятельно оформляет заказ по единой розничной цене. Партнёр получает фиксированную комиссию по SKU. Установите «Розничная цена (minor)» и «Комиссия (minor)» в `/admin/catalog` → товар → вариант. Суммы задаются в копейках; цена и комиссия сохраняются в заказе. Цена не зависит от партнёра.

1. `/admin`: очереди новых/зависших заказов, неоплаченных доставок, возвратов,
   приёмок/возмещений, выплат и склада. Счётчик открывает соответствующие заказы.
2. Сверить получателя/состав. NEW → CONFIRMED → FULFILLING — согласование/сборка,
   не оплата. До отправки отмена освобождает резерв. Для изменения состава/цен
   нужна отмена и новый заказ; история не редактируется.
3. «Фактические деньги»: только сверенные поступления, сумма **в копейках BYN**,
   фактическая дата, основание и уникальный безопасный reference без карты/IBAN/
   секретов. При потере ответа повторять исходную операцию. Ошибка — отдельное сторно.
4. SHIPPED — после реальной отправки: quantity/value/reserve списываются вместе
   один раз. После отправки отмена запрещена. Отказ/невыкуп — Return из SHIPPED,
   без вымышленного DELIVERED.
5. DELIVERED — подтверждённая доставка. Исходный hold (базово 14 календарных дней)
   не означает оплату. Недостаточное денежное покрытие блокирует release даже после hold.
6. REQUESTED Return: строки/количество/причина, блокировка affected строк.
   COMPLETED фиксирует финансовый возврат/обязательство, но не приёмку или перевод.
   REJECTED не начинает новый hold после истечения первоначального.
7. Отдельно отметить физически полученное/проверенное количество и пригодную часть.
   Только пригодное добавится на склад один раз с исходной C. Брак/потеря остаётся
   потерей стоимости; старые резервы не реактивируются.
8. Возмещение покупателю выполнить вне приложения по разрешённому процессу, затем
   записать фактический REFUND на обязательство. Переплата — тоже обязательство,
   не дополнительный заработок. Завершённый Return сам денег не переводит.
9. Записать фактические прямые расходы, явно подтвердить их проверенный итог,
   включая 0. Пустой review — неизвестно; новая запись делает старый review неполным.
10. REQUESTED выплата блокирует доступный остаток с учётом долга. После разрешённого
    внешнего перевода отметить PAID с его уникальным reference. REJECTED возвращает
    блокировку. Приложение не переводит деньги и не проверяет банк автоматически.

Поздний Return после PAID дописывает долг партнёра. Старые выплаты/allocations сохраняются;
новые заработки сначала покрывают долг. Сверять AVAILABLE/ожидается/заблокировано/PAID/долг.

Отчёт различает розничные продажи, комиссию, продажи за вычетом комиссии, фактические деньги и вклад. Вклад закрытой когорты учитывает исходную
C, пригодные приёмки и реальные расходы/потери без двойного вычета. Неизвестные C/
расходы показывают «нет данных», покрытая часть подписана отдельно. Даты создания,
доставки и денег не смешиваются. Это не налоговая или полная чистая прибыль.

Пополнения/коррекции — только с основанием и устойчивым ключом:
[CLI](native-inventory-t47.md). Ежедневно контролировать backups/alerts, перед
обновлением — encrypted backup/recovery. [Checklist запуска](production-launch-t45.md).
